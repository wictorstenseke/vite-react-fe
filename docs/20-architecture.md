# Architecture

This document provides a high-level technical overview of the project structure and key design decisions.

## Technology stack

| Layer | Technology | Notes |
|-------|-----------|-------|
| Framework | React 19 | Latest stable release |
| Language | TypeScript (strict) | Strict mode enabled |
| Build tool | Vite (Rolldown) | Rust-based bundler, ~5-10× faster builds |
| Styling | Tailwind CSS v4 | Utility-first, PostCSS-based |
| UI components | shadcn/ui + Radix UI | Accessible, unstyled primitives |
| Routing | TanStack Router | File-based, fully type-safe |
| Data fetching | TanStack Query | Caching, background refetch, mutations |
| Testing | Vitest + Testing Library | Co-located tests, jsdom environment |
| Linting | ESLint + Prettier | Import ordering, unused import detection |
| CI/CD | GitHub Actions | Defined in `.github/workflows/` |

## Routing

TanStack Router uses **file-based routing**: every file in `src/routes/` becomes a route automatically. The route tree (`src/routeTree.gen.ts`) is generated by the Vite plugin and is git-ignored.

To add a new page:

```tsx
// src/routes/about.tsx
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/about")({
  component: AboutPage,
});

function AboutPage() {
  return <div>About</div>;
}
```

No manual registration required — the Vite plugin detects the new file automatically.

## Data fetching

TanStack Query is configured in `src/lib/queryClient.ts` with sensible defaults:

| Setting | Value | Reason |
|---------|-------|--------|
| `staleTime` | 5 minutes | Data stays fresh for this duration |
| `gcTime` | 30 minutes | Unused cache entries are garbage collected after this |
| `retry` | 1 | One automatic retry on failure |
| `refetchOnWindowFocus` | `true` | Keeps data fresh when user returns to the tab |
| `refetchOnReconnect` | `true` | Refetches after network reconnection |

Custom query hooks live in `src/hooks/` and follow the pattern in `usePosts.ts`.

## API client

`src/lib/api.ts` provides a typed `fetchJson` wrapper that:

- Prepends `VITE_API_BASE_URL` to all relative paths
- Throws on non-2xx responses with a structured error
- Is importable as typed resource clients (e.g., `postsApi`)

## Layout system

`AppShell` (in `src/components/layout/`) provides:

- Sticky header with theme toggle
- Responsive container (max-width + padding)
- Footer
- Mobile-first responsive design

The root route (`src/routes/__root.tsx`) renders `AppShell` and all child routes are rendered inside it.

## UI components

shadcn/ui components are installed via the CLI into `src/components/ui/`. They are owned by this project (not a dependency) and can be freely modified.

Add new components:

```bash
npx shadcn@latest add <component-name>
```

See [shadcn/ui documentation](https://ui.shadcn.com) for the full component catalogue.

## Testing architecture

Tests are co-located with source files using `.test.tsx` / `.test.ts` extensions. See [docs/testing.md](./testing.md) for full details.

Key utilities in `src/test/utils.tsx`:

- `createTestQueryClient()` – QueryClient with test-safe defaults (no retries, no logging)
- `renderWithQueryClient()` – Wraps components in `QueryClientProvider` for testing
